# 2026-08-18 — kit 2.4.0: vendored gates

**Origin:** juce-rag resident session, 2026-08-18, executing the fleet-wide
kit 2.4.0 mechanical migration relayed by the human (not a retrofit: no
survey, no rung, no plan-pause — two deterministic commands and a check).

**Why.** Kit gate code used to be COPIED per repo. Measured across the fleet
on 2026-08-18: ten distinct `leak_gate` implementations, nine missing the
Windows identity pattern, every one declaring a `kit_version` that promised
it. A version was a claim about a copy, and a copy can lie. From 2.4.0
mechanism is vendored to `.kit/` and pinned by sha256; substance (charter,
ROADMAP, DECISIONS, LIBRARY) is untouched.

**What changed.** `kit_sync.py .` (already current — `.kit/kit-gates.sh` +
`.kit/MANIFEST` were installed by an earlier sync, untracked).
`migrate_to_vendored.py . --apply`: `verify` 104 → 48 lines, 56 kit-owned
lines removed (`record`, `leak_gate`) and replaced with a
`. .kit/kit-gates.sh` source plus `kit_integrity` in `fast`. Project gates
untouched — `check_p0.py` wiring and the honest `full` == fast survive
verbatim. The uncommitted 2.3.0 plant-hiding patch is subsumed: migration
deleted the block it patched.

**Evidence — declared vs effective.** Declaration was withheld until the
tree earned it, then proven:
- `./verify fast` green, project gates still print (`check_p0: OK`).
- Reachable, not merely present: `grep -c 'kit/kit-gates.sh' verify` → 3.
- Fires, POSIX: planted `/Users/somebody/private` → named hit, exit 1.
- Fires, Windows: planted `C:\Users\somebody\private` → named hit, exit 1.
  (This repo already carried the Windows pattern from the 2.2.1 retrofit;
  re-tested rather than assumed.)
- `kit_integrity` is live, not inert: appending a byte to
  `.kit/kit-gates.sh` → exit 1, "was edited — it is kit-owned"; restoring →
  exit 0; sha256 matches `.kit/MANIFEST`.
- `currency.py` → `declared: 2.4.0  CURRENT  nothing to do`.

**Finding reported upstream.** Before the migration, `currency.py` scored the
2.4.0 requirement `[x]` on `.kit/` matching canonical while `verify` still
held inline gates and never sourced them — the checker tests that the
vendored file is correct, not that the oracle reaches it. Declaring on that
alone would have been a false declaration of exactly the kind 2.4.0 exists to
end. Raised with the human; the sync's own "reachable, not merely present"
check (three repos read `sync: current` while ungated) covers the same gap.

**Verify:** `./verify fast` green. Git hash: this commit.
